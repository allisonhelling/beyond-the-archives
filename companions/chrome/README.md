# Beyond the Archives Companion (Chrome / Edge)

For the inline library controls in iOS Safari's free Userscripts app, see [the userscript companion](../safari/README.md). Build its installable file with `npm run build:userscript`.

This Manifest V3 extension is part of the hosted library project. It captures metadata for explicitly requested work imports, refreshes, series previews, and library listing scans on the connected website. It also adds the shared Safari library bar directly to AO3 work, chapter, and series pages, and to visible work tiles on AO3 listings, search results, tag pages, bookmarks, and author profiles. Visiting a page never creates an import job or automatically saves a work. Once paired, the bar loads your saved details for that page.

Explicit chapter read actions count the loaded chapter locally and save only its chapter number/ID, word count, server timestamp, and reread flag in the existing private reading history. Summaries and notes are excluded; unavailable text produces an unknown count, and skipped chapters are not estimated. The web app shows these records under **Chapter Reading History** on the work info page. Apply `20261024000500_chapter_read_history.sql`, deploy the website, then rebuild and reload the extension. See the [shared feature notes](../../docs/IMPLEMENTATION.md#ao3-metadata-capture-and-display) for counting and backup behavior.

When viewing **Entire Work**, the shared reading bar appears after every numbered chapter, including its end notes. **Mark Read**, **Finish Fic**, and **Re-Read** use that chapter; all bars share saved progress, theme, and connection state. Word counts cover only the chapter explicitly marked read. Rebuild and reload the extension or replace the installed userscript to use this change.

## Deploy the Hosted Boundary

1. Apply the project migrations through `20261016000800_existing_import_reading_location.sql` to your Supabase project using your normal migration workflow (`supabase db push` for a linked project). Existing direct imports keep their behavior.
2. Deploy `supabase functions deploy extension-metadata`. Keep the supplied `verify_jwt = false` function setting: the handler itself verifies every bearer token with Supabase Auth, including projects with modern signing keys. Service-role credentials stay inside the Edge Function.
3. Deploy the updated website. The mode selector is under **Settings → AO3 metadata retrieval**.

These instructions describe deployment; building locally does not apply migrations or publish the function or website.

## Build and Install

Configure the public hosted Supabase settings and exact website origin (no path) in `.env.local.hosted`:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your_public_publishable_or_anon_key
EXTENSION_APP_ORIGIN=https://your-library.example.com
```

Then run:

```sh
npm run build:extension
```

The build reuses the app's public-key validation and writes `extension/dist/manifest.json`, `background.js`, and `content.js`. Only public configuration is embedded. The generated directory is ignored by Git. The standard build includes Hosted from `.env.local.hosted` and Local from `.env.local` when configured, and defaults to Hosted. Explicit environment variables override the primary build profile. The older `npm run build:extension:local` command remains compatible and defaults to Local. A build accepts messages from exactly that configured website origin; build again if the origin or Supabase project changes.

The Supabase URL and public key must match the connected website's project. A hosted website combined with a local backend is rejected before generating files. To build the hosted companion, run:

```sh
npm run build:extension
```

This uses the hosted public configuration without changing the app's local Supabase settings. Confirm `extension/dist/manifest.json` lists your hosted website under `externally_connectable` and your hosted Supabase project under `host_permissions`. Origins in `*.test.js` are test fixtures and do not configure the installed extension.

Open `chrome://extensions` or `edge://extensions`, enable Developer mode, click **Load unpacked**, and select `extension/dist`. Allow access to AO3 and the configured Supabase project. Copy the extension's ID into the hosted site's Settings, choose **Browser extension**, and click **Save metadata mode**. An optional `VITE_AO3_EXTENSION_ID` frontend build variable supplies the default ID; the Settings field overrides it on this device. For distribution, package the generated directory and follow Chrome Web Store / Edge Add-ons publishing; an unpacked install is sufficient for personal use.

When using local Supabase, start its Edge Function handler in a separate terminal and leave it running:

```sh
npx supabase functions serve extension-metadata
```

The extension can connect to Supabase Auth while this handler is stopped, but uploads and timeout reports will fail and hold up the import queue. A `503` with `name resolution failed` from `/functions/v1/extension-metadata` means the local Edge Function runtime is unavailable. Start it, then reconnect the extension in Settings. Older requests that have already failed can be retried from import history.

For local use, run `npm run dev` and open `http://127.0.0.1:5173/settings` (use the port printed by Vite). After rebuilding the extension, click **Reload** on its card in the browser's extensions page. `https://library-extension-test.example` is intercepted only inside the automated browser test; opening it normally produces a DNS error. Tests build their extension in a temporary directory so your installed `extension/dist` keeps its configured origin.

## Pair the AO3 Bar

Use one installed **Beyond the Archives Companion** for both environments. Click its toolbar icon (or open **Extension options** on its Extensions card) and choose **Hosted** or **Local**, then click **Switch environment**. The selector lists the configured website, defaults to Hosted, and remembers your choice. Disable the older separate local extension to avoid two companions competing for the AO3 bar.

Pause running scans and finish current imports, previews, or saves before switching. Reload open AO3 tabs afterward; their bar shows the active environment and warns if it has changed. Requests from an inactive website and stale AO3 tabs are rejected instead of being sent to another database. Draft edits in stale tabs continue to be preserved for their original environment.

Pair once in each environment. Switching back reuses that environment's pairing until it expires or is revoked. Device credentials, drafts, import sessions, paused scans, captured pages, and Quick Sync baselines stay separate. Import sign-in tokens remain in session storage; a browser restart still requires reconnecting imports, while the bar's device pairing persists.

In both websites' metadata settings, enter the same installed extension ID. If Local is absent from the selector, configure local public settings in `.env.local`, rebuild, and reload the extension. Use `EXTENSION_LOCAL_APP_ORIGIN` for a nondefault local website port; optional `EXTENSION_LOCAL_SUPABASE_URL` and `EXTENSION_LOCAL_SUPABASE_PUBLISHABLE_KEY` environment variables override the local backend during builds.

After rebuilding, reload Beyond the Archives Companion at `chrome://extensions` (or `edge://extensions`), then reload AO3. Existing AO3 tabs need a reload to receive the new content script.

1. Open the library website’s **Settings → AO3 Browser Bar**.
2. Give this browser a device name and create a pairing code.
3. Open an AO3 work or series page, click **Connect Library**, and paste the code within five minutes. Reload other open AO3 tabs after pairing.

The bar reuses the Safari editor, personal controls, progress buttons, theme, and conflict review. Series controls appear after all series information and stats, immediately before the works list; each work’s bar follows its listing data. Chrome bar text matches the computed AO3 summary text size. Work pages also have a reading-progress bar near the bottom. Links display the library logo and chapter progress uses read / published counts.

Bar pairing is separate from the website’s import/scan connection. It stays connected across browser restarts and website sign-outs until disconnected here or removed in the app. Revoke it from AO3 Browser Bar settings or **Disconnect device** in the bar. Drafts remain local to the paired account. Apply `20261026000200_persistent_companion_pairings.sql` for indefinite connections; unused pairing codes still expire after five minutes. Active connections are migrated without re-pairing. Previously expired credentials remain invalid.

The content script runs in Chrome’s isolated world with a closed shadow root. It communicates only with the extension’s internal message handler. That handler restricts requests to AO3 work/series tabs, bar-specific storage keys, and the fixed library RPC. Credentials and drafts use extension-local storage; import tokens and scan checkpoints are not exposed by the bar bridge. Nothing uses AO3 local/session storage or page messaging.

## Behavior and Connection Lifetime

- New import/refresh jobs snapshot your selected mode. Changing Settings does not move existing jobs between modes; cancel an old batch and submit again to change its mode.
- The website sends the extension a short-lived Supabase access token through the browser's external-messaging API. The manifest and background worker both restrict the sender to your configured website origin. AO3 pages never receive that token. It is stored only in `chrome.storage.session`, with no refresh token.
- The extension claims only your outstanding extension jobs. It handles one work at a time, reuses a matching AO3 tab, or navigates its own background tab for successive captures. It creates that tab only when needed. It captures only metadata, summary and chapter-navigation elements; no chapter text, account forms, or cookies are uploaded. Your browsing tabs are never closed or redirected.
- After a successful import, the browser checks for the next queued work after 3 seconds. Imports remain sequential, and the next work waits for the current page’s metadata to be ready and saved. A 30-second background alarm still checks for new jobs and retries interrupted requests; page-load events also trigger checks. Keep the browser running. Opening the website refreshes the connection; after a browser restart or expired login, reconnect from Settings. `AUTH` on the extension badge means reconnect; `WAIT` means a requested page is waiting; `!` means a request failed and will be retried while the lease remains valid.
- Requested tabs can supply metadata before images and other resources finish loading. An early check waits up to 8 seconds for the HTML to be parsed and the title, byline, fandom, rating, word count, and chapter count to be present. Full-load checks remain the fallback for sparse pages or an early miss. Chapter navigation and optional fields come from the parsed document; login and confirmation pages are not imported. Overlapping checks share the existing sequential job processor. The `webNavigation` permission supplies an AO3-only, main-frame DOM-ready event; ordinary visits still do not create import jobs or trigger capture. Reload the extension after rebuilding and accept its updated permissions if Chrome requests them.
- Finish AO3 sign-in, adult-content confirmation or a blocking challenge yourself in the requested tab. The extension captures only after the requested work loads successfully. After about five minutes it records a retryable failure; retry explicitly from import history. Network outages preserve the request until the lease expires; fencing tokens reject late, cancelled, or superseded uploads.
- Browser-supplied metadata is stored privately on the requesting library entry. The existing server parser and validator process it; manual overrides take precedence. Shared AO3 metadata and manual corrections are preserved. Explicitly importing a verified chapter URL sets fully read chapters to the linked chapter position minus one, including for an existing fic and when returning to an earlier chapter. A To Read fic becomes Reading when at least one chapter is read. Metadata-only refreshes preserve the current reading location. Personal edits made while retrieval is pending take precedence over delayed results. Chapter links can use private verified mappings.
- All requests already authorized in your account can continue when the website tab closes, until the extension's short-lived token expires. Signing out through an open app disconnects its extension session. Browser restart clears it. Ordinary AO3 browsing never creates work requests.

### Series Previews

Rebuild and reload the extension after updating. In the importer, explicitly loading an AO3 series preview opens the first series page in a separate extension-owned window, captures its listing, description and work blurbs, then follows each Next link in its extension-owned preview tab and combines the work previews. Successive series pages and previews reuse the window and its tab; closed preview tabs or windows are recreated. Existing browsing tabs are left in place. Sample work previews use a separate reusable tab; queued work imports have their own reusable tab so active captures do not redirect one another. It does not open the listed works or create imports. Previews also capture parsed HTML without waiting for images or other resources, and use a two-minute elapsed-time deadline. Complete sign-in/confirmation in the AO3 tab within two minutes, or retry the preview. Deploy the `series-preview` function and apply the series-preview migration before using this feature. Link imports keep previews for Back and retry within the current import, and saving series details reuses a complete preview. Selected linked works use the existing import queue after confirmation. Long **Choose Works From Series** reviews hide work lists by default behind **Show Series Works** and target 30 entries per page while keeping each series together. A series stays on the page that would hold more of its works, with ties staying on the earlier page; pages may exceed 30 entries, with shared pagination controls above and below the list. Selections, bulk actions, saving series details, and imports apply across every page. New bookmark-only scans separate **Bookmarked Series** from **Series Containing Bookmarked Works**, showing explicitly bookmarked series first. A series found both ways appears only in Bookmarked Series. Selected works without individual bookmarks use the series bookmark date to determine reading status and progress. Works updated before that date are Finished; otherwise they are Currently Reading, with chapter progress unconfirmed unless **Check chapter publication dates** is enabled. That option also checks series works against the series bookmark date. Individually bookmarked works use their own bookmark data. Series bookmark IDs, notes, tags, and Rec markings are not copied to the works. Older saved scans retain their original order because their bookmark sources were not recorded; start a new scan after rebuilding and reloading the extension to use these groups.

## Bookmarks and Marked for Later Sync

Apply migrations through `20261022000400_library_sync.sql`, deploy the updated website, rebuild with `npm run build:extension`, and reload the unpacked extension in Chrome. Accept the added `unlimitedStorage` permission, used for durable large-library checkpoints. Reconnect in Settings with the extension ID. No new Edge Function or Python installation is required for listing sync.

Open **Mass Import from AO3 → AO3 Library Sync**. Paste an unfiltered URL:

- `https://archiveofourown.org/users/USERNAME/bookmarks`
- `https://archiveofourown.org/users/USERNAME/readings?show=to-read`

Run **Full library scan** for each list initially, then choose **Import scanned works**. Subsequent **Quick Sync** runs use that list's acknowledged record IDs (bookmark IDs for Bookmarks, work IDs for Later). Bookmark requests explicitly use creation date descending. Quick Sync stops after the first overlapping page, retaining every row on that page for new imports or existing metadata refresh; it cannot detect removals or additions behind the overlap boundary. Use a full scan if list ordering changes. Both modes keep existing personal data, including manual metadata corrections, notes, personal tags, ratings, and progress. Non-empty AO3 work metadata refreshes automatically for observed works (including zero statistics and false completion flags). Empty fields preserve saved values. Bookmark differences appear after scan import under **Bookmark Conflicts — Review Personal Data**. Choose **Keep Saved Data** or **Use Incoming Bookmark** for each work; saved data stays unchanged until an incoming choice is applied. Incoming deleted bookmarks replace only notes/tags. Concurrent edits require a fresh review. CSV import retains its separate Keep/Overwrite choices. Apply migrations through `20261027000400_library_sync_bookmark_choices.sql` before using the incoming-bookmark action.

The listing selectors are ported from `ao3_scraper/ao3_export.py`. The existing JavaScript CSV row converter and database importer validate and save new works. Listing sync completes its import jobs in the same transaction without fetching individual work pages. New bookmark notes and tags follow CSV import rules; chapter progress stays unconfirmed unless the optional Chapter Index check is enabled. Series listings, bookmarked series, and series memberships linked in primary work blurbs expand into their paginated work lists for scanning. The scanner does not recursively discover other series from those expanded installments. Settings → Series Imports chooses whether to import all available installments or choose works each time; each import can temporarily reverse that default. In choose mode, the shared series picker opens in a popup and uses series previews saved with scan checkpoints, combining paginated works without requesting those pages again. Older compatible checkpoints use their saved work rows; saving full series details fetches missing series-level information only when needed. Choose installments or skip each series while directly listed works stay included. Username imports also wait for these selections. Summary and Tags collapse independently; the bottom controls hide details, select available works, or save all series details. Saving series details does not import works. Canceling returns to the saved scan, and retrying an interrupted upload retains the current selections. Rebuild and reload the extension for this behavior; series scans captured before this update must be discarded and scanned again because their checkpoints do not distinguish direct works from series installments. External bookmarks are counted as skipped. Deleted-work bookmarks retain their bookmark IDs, URLs, multiline notes, tags, dates, users, counts and any remaining bookmark status; `work_status` is a separate field. Source bookmark observations are retained separately from personal notes and tags, and blank deleted-work fields never replace previously saved work metadata. No work-page request is made for deleted bookmarks. Both scan modes automatically mark explicitly deleted bookmarks with the Deleted publication status while preserving all saved metadata. Absence alone never implies deletion. A metadata refresh that receives AO3’s explicit Error 404 page asks the owner whether to mark the work deleted; confirming changes only availability and preserves saved information. Work and bookmark source rows have separate Quick Sync identities; the library's existing model still has one entry per work, preserving the first saved entry when the work occurs in both lists.

**Check chapter publication dates** is off by default in the **Import Bookmarks** dialog. CSV import has its own **Check chapter publication dates for bookmarks** option. With it enabled, eligible bookmark scans reuse the extension-owned scan tab to visit each work’s `/navigate` Chapter Index, using the selected request interval. Only dated, available bookmarks needing chapter inference are checked; already-known bookmark IDs are included when **Review Existing Entries** is enabled in a Full Scan; Marked for Later and explicit list statuses other than Reading are skipped. The existing parser checks work identity and chapter positions, and only complete indexes are saved into page checkpoints. Pauses, restarts, sign-in alerts, and partial page limits retain the chapter-check state. The importer estimates a consecutive read prefix strictly before the bookmark day; same-day, missing, ambiguous, or unavailable dates remain unconfirmed. Existing library progress is preserved. CSV imports use the existing metadata queue and may open additional AO3 pages only for chapter-date checks when selected; choosing Overwrite still controls whether existing personal data changes. This is an estimate based on a bookmark’s date, not an AO3 record of actual chapter reading. Apply `20261023000200_optional_bookmark_chapter_dates.sql`, deploy the updated `extension-metadata` function, and rebuild/reload the extension.

Scans use a separate local checkpoint state and one extension-owned AO3 tab, never redirecting existing browsing tabs. They wait for the current work job or series preview, then hold new work claims until paused or finished. The request interval defaults to 15 seconds and can be set to 5–3,600 whole seconds before or during a scan. Use Apply request interval to update a running or paused scan; the value is saved with checkpoints and used on resume. The first tab opens as soon as active work and existing request cooldowns allow, without an extra initial interval. A small random delay spaces later requests; a timer wakes the scan when due, with Chrome's alarm as a service-worker recovery fallback. Listing and Chapter Index capture starts once the requested HTML is parsed, even if Chrome is still loading images or other resources. Unparsed or missing document results are checked again without reloading until the existing two-minute timeout; equivalent query encodings are accepted. Work imports retain their existing three-second queue interval. The request gate prevents imports/previews from opening a new page during a scan's cooldown. This coordinates this extension's traffic only, not other browsers or the hosted worker.

Pause, resume, or discard from the importer. Error, login, redirect, missing-tab, timeout, or restriction pages pause the scan rather than retrying automatically; an app-wide dialog reports the interruption even outside the importer. Its Open Tab button focuses the existing tab and its browser window without sending a new page request. Resolve the issue and resume manually when appropriate. Dismissing an alert suppresses repeat polling alerts for that interruption; a new interruption produces a new alert. DOM capture cannot read HTTP status or Retry-After headers, so no automatic rate-limit bypass or retry is attempted. Five hundred pages is a batch boundary. Use **Import Batch and Continue** to save collected pages and resume pending listings and series; an intermediate batch does not advance the Quick Sync baseline.

Each successful page is saved in extension local storage, scoped to the connected library account. Tokens remain session-only. Checkpoints survive service-worker/browser restarts; reconnect the same account to continue. Saved private notes stay on this device until imported or discarded. Completed baseline IDs remain until extension storage is cleared/uninstalled. Page-sized database transactions permit libraries larger than the CSV form's 2,000-work submission limit. An interrupted upload can be retried safely: existing works are kept, and baseline IDs advance only after all saved pages have been acknowledged. Different website tabs cannot acknowledge a replacement scan by accident. Closing the website does not cancel scanning while the session is valid.

### Local Build, Page Ranges, and Sample Imports

Run `npm run build:extension:local` with the local app's public Supabase configuration in `.env.local`. This reads development configuration, ignores the hosted `EXTENSION_APP_ORIGIN`, and writes **Beyond the Archives Companion (Local)** to `extension/local/dist`. The standard shared extension in `extension/dist` is preserved; using its environment selector is the recommended testing workflow. The public manifest key gives the local companion a stable ID, selected automatically by the app on loopback hostnames; both local and hosted Settings accept the shared extension ID, while the local build ID remains a fallback.

Load the local folder in Chrome (replace an older local installation without the fixed ID once), use `http://127.0.0.1:5173`, and reconnect in Settings. For another local origin/port, set `EXTENSION_LOCAL_APP_ORIGIN` when building; it must match the website exactly. Apply pending local migrations with `npx supabase migration up --local`, without resetting the database.

Library Sync exposes optional **Start page** and **End page** in both the hosted and local app. Both are inclusive and accept positive safe whole page numbers; page numbers may exceed 500. Blank Start defaults to 1; blank End continues to the list’s end, using 500-page batches. Ranges survive pause/resume, and checkpoints retain their actual AO3 page numbers. Ranged imports keep existing works and never establish or advance the full-list Quick Sync baseline. Quick Sync requires page 1 without an end limit. The previous local-only page-limit control has been replaced.

For sample-library imports, run `npm run dev:sample` with the local extension loaded. The importer connects automatically using a tokenless message accepted only by the local extension’s restricted website origin. No Supabase account is required; no backend jobs are claimed in sample mode. Scans still require explicit activation and your normal AO3 session. Imported rows reuse the CSV converter and sample-story validation, persist only in browser sample storage, and preserve existing personal edits. Sample checkpoints and baseline IDs use a separate storage slot from account imports. Opening the normal connected app reconnects authenticated workflows. Sample mode also exposes the existing **Import Work or Series Links** form. Work captures reuse the explicit preview controller and metadata parser; series previews use the existing work picker and local parser without calling an Edge Function. Only local sample sessions can request direct work captures through this path; normal authenticated work imports retain their existing claimed-job flow. Sample imports preserve existing works, apply the chosen reading status, and use verified chapter options for progress. Keep the app open during imports; successive new work captures wait 15 seconds. CSV imports and account import history remain in the connected app.

Bookmark scans also capture `bookmark rec`: `true` for a visible Rec icon, `false` for a normal public bookmark icon, and `unknown` for private/hidden bookmarks or missing evidence. On first import, a visible true Rec initializes the tracker’s editable Rec status; false or unknown starts unselected. Click the heart on a work tile or its details page to change it. The Recs shelf, filters, automatic collections, and CSV rec column use this personal status independently of Favorites. Later imports refresh the source observation without changing your choice. Apply migration 20261022001100_editable_recs.sql for this behavior. Personal Notes filters require non-whitespace private notes. Content Rating filters AO3 ratings; Rating independently selects personal star ratings (including Unrated), with multiple selections combined using OR. These conditions also work in automatic collections.


### Repeat Imports and Other AO3 Lists

**Import Bookmarks** and **Import Marked for Later** ask for an AO3 username, with an optional save checkbox. Saved usernames prefill the Bookmarks dialog so chapter-date checks remain available; Marked for Later skips the prompt on later imports. Settings → AO3 Username lets you view, change, or delete this browser preference; accounts and sample mode have separate values. These buttons start the selected scan mode and automatically import completed pages while the importer is open. Return to the importer to upload scans completed while it was closed. Existing library entries and personal edits are preserved.

**AO3 List URL** remains independent of the saved username. Full scans accept user and pseud Works/Bookmarks/Series lists, Marked for Later, filtered `/bookmarks?...` URLs, tag work/bookmark listings, and work search results. Filters in a full-list URL are preserved; use the page-range controls for page limits. Quick Sync remains limited to unfiltered user Bookmarks/Marked for Later lists. Series encountered in any listing are expanded once per scan; inaccessible pages pause safely. New works from ordinary Works or Series pages default to To Read.

A collection home or profile URL scans both its Works and Bookmarks. A direct collection Works/Bookmarks URL scans that particular list and preserves filters. **Import to New Collection** scans the unfiltered collection profile, Works, and Bookmarks and creates a manual custom collection containing new and existing imported works. The description combines the AO3 summary and Intro as plain text. You can change the new collection name before importing, including when a previous collection already uses the AO3 title. Page ranges and Quick Sync are unavailable for combined collection scans and series indexes. Scans share the existing single tab, request pacing, checkpoints, and a 500-page batch boundary across every source. **Import Batch and Continue** imports saved pages before continuing with pending list and series pages. Existing limit-paused scans can use **Prepare Saved Batch** after updating, without discarding their checkpoints; rebuild/reload the extension after updating.

## Shared Rating Explanations and Reading Controls

Apply `20261024000100_shared_personal_rating_info.sql`, deploy the web app, and rebuild/reload the companion. **Connection → Rating Info** now reads and saves the same account setting as the app’s **Settings → Personal Rating**. Blank text hides the info icon across devices. Reloading the bar, returning to its AO3 tab, or opening Rating Info refreshes the saved explanation. **Cancel** discards unsaved explanation edits and closes the editor. Concurrent edits are rejected rather than overwriting a newer explanation.

Tap or click the chapter count in either bar to open **Edit Chapter Progress**, enter **Chapters Read**, and choose **Save Progress**. Both bars update together; Cancel or Escape closes without saving. Failed saves retain the entered count for retry. This corrects saved progress without creating chapter word-count records. Saved work bars use matching button heights and show **Pause** or **Resume** with their icons in both companions. Pause preserves progress and records the pause; Resume restores Currently Reading or the previous Re-Reading status. On the first unread chapter of a paused fic, the top bar offers Resume and the bottom bar offers Mark Read. Later unread chapters offer Mark Read in both bars without Resume.

- On an unsaved work’s first chapter, the top bar offers **Add to Library**, **To Read**, then **Reading**. To Read saves zero chapters read; Reading saves Currently Reading at chapter 1 with zero chapters read. To Read does not appear in chapter bottom bars or later chapter bars. The first chapter’s bottom bar and both bars of later chapters offer **Mark Read**, which saves the work and marks that chapter and all earlier chapters read. The bottom bar of a complete fic’s final chapter offers **Finish Fic** instead (including one-shots), saving it as Finished. These read actions record only the selected chapter’s word count, not counts for earlier chapters. Entire Work uses the same actions after each numbered chapter. Listing tiles retain their existing To Read shortcut. Rebuild/reload Chrome/Edge Companion v0.7.5 or replace the Safari v0.1.5 userscript to use these controls. On a known chapter, **Add to Library** prefills the current chapter. Completed chapters show **✓ Read** beside the chapter count. For a To Read fic on chapter 1, the top bar offers **Start Reading** without advancing progress; the bottom bar offers **Mark Read**. Later To Read chapters offer Mark Read in both bars. Active reading offers **Read** and **Pause**, retaining **Finish Fic** on a complete work’s final chapter. Mark Read on a final To Read or paused chapter also finishes the fic. Finished works offer **Re-Read** with a reread icon on every known chapter; selecting it switches to Re-Reading at that chapter, with earlier chapters counted as completed. Reading the latest WIP chapter keeps the work in progress.

## Wayback Work Imports

Chrome/Edge Companion v0.7.6 supports fixed Wayback Machine snapshots of AO3 works in the app’s link importer and bulk URL form, including local sample imports. Rebuild and reload the extension and accept its added `https://web.archive.org/*` permission. Apply `20261027000500_wayback_work_imports.sql` and deploy the updated website and `extension-metadata` function first.

The app requests the archived tab explicitly and captures only AO3 metadata. Historical metadata remains private and manual corrections retain precedence. The saved snapshot URL is preserved; imports do not fetch live AO3 instead or infer that a work is currently deleted. Archive pages without accessible work metadata remain retryable/editable according to the normal import result. Archived series, listing scans, and wildcard capture/history URLs are unsupported. See [Wayback implementation details](../../docs/IMPLEMENTATION.md#wayback-work-imports) for worker rollout and limits.
