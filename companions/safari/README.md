# AO3 Library for iOS Safari / Userscripts

This companion runs in the free [Userscripts app](https://github.com/quoid/userscripts). It adds an inline, compact library panel to AO3 work/chapter and series pages. It shares the tracker's URL/progress helpers, reading statuses, public-key validation, and atomic database save; it does not require the Chrome extension.

Chrome and Edge use the same bar and editor through the [native AO3 Library Companion extension](../chrome/README.md#pair-the-ao3-bar). Each browser has its own pairing and local drafts.

Explicit chapter read actions count the loaded chapter locally and save only its chapter number/ID, word count, server timestamp, and reread flag in the existing private reading history. Summaries and notes are excluded; unavailable text produces an unknown count, and skipped chapters are not estimated. The web app shows these records under **Chapter Reading History** on the work info page. Apply `20261024000500_chapter_read_history.sql`, deploy the website, rebuild the userscript, and replace the installed file. See the [shared feature notes](../../README.md) for counting and backup behavior.

On series pages, the series bar appears after the series information and stats, immediately before the works list. Every recognized work tile has its own library bar below its metadata and statistics.

## Deploy and Build

Apply migrations through `20261019000100_userscript_metadata_refresh.sql` to the intended Supabase project (`supabase db push` using your normal linked-project workflow), then deploy the website. No additional Edge Function is required. Local builds do not deploy these changes.

For an iPhone, put the same hosted public project configuration as the deployed website in `.env.local.hosted`:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your_public_publishable_or_anon_key
EXTENSION_APP_ORIGIN=https://your-library.example.com
```

```sh
npm run build:userscript
```

Output: `userscript/dist/ao3-library.user.js` and a metadata file. Every userscript build loads `.env.local.hosted` and requires hosted HTTPS backend and app origins. Localhost builds are rejected before writing files. Explicit environment variables can supply hosted public settings in CI. `npm run build:userscript:hosted` is an alias of the same build command; there is no local userscript build mode.

## Install and Connect

1. Install Userscripts, open its app, and select a scripts directory accessible in Files.
2. Copy the generated `ao3-library.user.js` into that directory. Alternatively host it at an HTTPS URL ending in `.user.js`, visit that URL in Safari, and use the Userscripts popup's install prompt. The build does not host the file automatically.
3. Enable Userscripts under Safari extensions in iOS Settings. Allow it on `archiveofourown.org`; do not grant broad access to all websites. If Safari asks for network access, allow only your configured Supabase backend. The script matches HTTPS AO3 work URLs only, skips frames, and sends requests only to that compiled backend. Userscripts' documented metadata does not provide a `@connect` network allowlist; destination restriction is enforced by this script's fixed request URL and Safari permissions.
4. Open the Userscripts Safari popup once to load the new file, then reload an AO3 work.
5. Sign into your library website and open **Settings → iOS Safari userscript**. Name the device and create a code. Copy the full code into **Connect Library** on AO3 within five minutes. Codes are single-use and creating another replaces unused codes. Never paste a password, AO3 credential, or Supabase session token.
6. Refresh devices in Settings to see the paired device. Disconnect there to revoke access remotely, or use **Connection → Disconnect device** on AO3. Local disconnect requires backend confirmation; if offline, revoke from Settings on a connected device. Device authorization expires after 90 days; create another code to reconnect. Website sign-out does not revoke paired devices.

## Connection Troubleshooting

If the AO3 panel cannot reach the backend, rebuild with `npm run build:userscript` and replace the installed file. Open the Userscripts popup, then reload AO3. Old development builds may point at localhost and cannot connect to your Mac from an iPhone. All new builds require the hosted backend. If switching from a development build, create a fresh pairing code on the hosted library website; device connections are scoped to each backend. Never share the code.

For a hosted build, check the phone's connection and Userscripts' network permission for the configured Supabase host. Rebuilds do not update the file already installed in Userscripts.

## Reading Controls

- Chapter 1 defaults to To Read, a middle chapter to Currently Reading with the preceding chapters completed, and a known final chapter of a complete multi-chapter work to Finished. A one-shot remains To Read when first opened; the latest published chapter of an unfinished work remains Reading. Defaults are editable.
- The toolbar and editor use the same current chapter, separate from completed chapters: chapter 4 means three fully read chapters, or four when **This chapter is finished** is checked. To Read saves zero completed chapters; Finished saves all published chapters. These two statuses hide the chapter fields. Currently Reading and Re-Reading show the current chapter and its finished checkbox; Re-Reading indicates a previous read while tracking the new one. Tap the info icons beside Reading status and Current chapter for these rules. For chapter URLs, position comes from AO3's chapter selector, never the numeric chapter ID. When position is unavailable or full-work view is ambiguous, enter the current chapter explicitly.
- Saved works show reading status, saved chapters read (`Ch. # / #`), **✓ Ch. #**, **Edit**, and a slider icon at the top. A second bar before kudos contains only progress and the completion control. Both update together. Currently Reading, Paused Reading, and To Read works all keep these chapter controls. Marking a To Read chapter switches it to Currently Reading. An already-read AO3 chapter shows a green, non-clickable **Read** indicator whenever saved progress is at or beyond that chapter, including revisits. On the known final chapter, **✓ Finished** also changes reading status to Finished. The latest published chapter of an unfinished work marks progress without finishing the fic. Ambiguous full-work views omit the chapter completion action.
- **Connection → Rating Info** opens your personal star-rating explanation. Edit the text and choose **Save Rating Info** to save it to your library account across paired browsers and devices. The same text is editable in **Settings → Personal Rating** in the web app. Bars refresh it when loaded, when the AO3 tab regains focus, or when Rating Info opens. Blank text hides the info icon beside **Clear Rating**. The explanation supports multiple lines and remains separate from library entry edits. Older device-only explanations can be copied into the editor with **Use this device’s previous explanation**, then saved to the account. Concurrent changes from another device require reloading the explanation before overwriting it. Apply `20261024000100_shared_personal_rating_info.sql` before using this version.
- **Connection → Dark Mode / Light Mode** uses a moon or sun button to switch themes for both reading bars, the editor, and help panels. The choice is saved on this device, independently of pairing or account changes. Until you choose, the initial mode follows your device preference. Dark mode uses a `#333333` background with light text and accents.
- The slider icon opens connection settings only. Change reading status or current chapter through **Edit**, which includes a pencil icon. The pairing panel has no chapter-adjustment or Finish Fic buttons. A failed progress save restores both reading bars and shows an error beside the bottom bar as well as at the top.
- On a known chapter, **Add to Library** prefills the current chapter. Both reading bars show **Ch. # Read** for completed chapters, **✓ Mark Read** for unread chapters, or **✓ Finish Fic** on a complete work’s final chapter (including one-shots). Finished works offer **Re-Read** with a reread icon on every known chapter; selecting it switches to Re-Reading at that chapter, with earlier chapters counted as completed. The latest WIP chapter uses Mark Read and keeps the work in progress.
- Click **Add to Library**, **Edit**, or **Connection** again to collapse its open panel. Reopening or switching panels retains the fields you filled in, including a pairing code until you connect or disconnect. Collapsing does not save to the library; **Cancel** discards the library draft.
- The editor supports private notes, personal tag chips, a visual 1–5 star rating, and membership in existing custom collections. The typing field starts at the width of its placeholder and grows with your text. On mobile, hold the grip beside it, drag to a gap between tags, and release to move the typing position without changing your draft or reordering tags. The Personal tags info icon sits to the right of the tag box and explains touch controls on mobile, with keyboard instructions shown only on desktop. Type a personal tag and press Enter to add it; duplicate tags are ignored. On mobile, tap a chip to select it with a red outline and stronger red background, then tap the same chip again to delete it. The selected label remains fully visible without an X or fade. On desktop, click a chip to remove it, use arrow keys to insert between chips, or press Backspace twice to delete the preceding chip. Select a star or use Clear Rating to return to Unrated. The notes text area grows while typing; Collapse and Expand sit to the right of the notes box; Collapse returns a long note to its default height and Expand shows its full length. Choose **Add to Collection** to search and select collections; after assignment, use the edit icon beside **Collections**. Series and individual installment fields use the same collection control. Create new collections in the tracker. **Reload Saved Entry** appears only for saved works.
- The **View in** button with the library logo opens a saved fic’s details page. Before the fic is saved, the button shows only the logo and opens the library. The top bar places this button on the left, chapter completion, Edit, and Connection on the right, and reading status and chapter count centered between the left and right controls. The top bar stays on one row at every width and scrolls sideways on narrow screens. A colored bullet separates reading status from chapter count. For saved works, the bottom bar centers its reading status, colored bullet, chapter count, and completion control. For unsaved works, the bottom bar mirrors the top bar, including Add to Library; its buttons open the shared editor or connection panel at the top. Both reading bars use 20px text; editor and connection panels use the Reading status label’s 17px font size; chapter counts show “chapters read” help on tap or hover; help icons sit to the right of their fields. Collection search uses a placeholder without repeated headings. Once connected, version and update instructions appear only while an editor or Connection panel is open. The instructions link opens Settings directly at the iOS Safari userscript section.
- “Saved” appears only after the backend confirms. Text drafts are preserved in Userscripts storage while typing and across failed requests/reloads, scoped to backend, account and work. Cancel discards the draft. Reconnecting to another account does not display the previous account's draft. Stale edits from another tab/device are rejected; use **Reload Saved Entry**, review the retained draft, then save. A response lost after saving can produce the same stale-entry prompt: reload to check the saved values first.

## Privacy and Updates

The script uses `@inject-into content` and the privileged `GM` storage/network APIs. Device credentials and drafts are never stored in AO3 local/session storage, page attributes or messages. Its closed shadow panel limits exposure of rendered private fields to page scripts. Anyone with access to the browser/device or Userscripts storage may still access saved drafts. Revoking a device prevents backend access; it does not erase its local drafts. The backend stores credential hashes and grants credentials access only to this companion's library operations. It does not grant a Supabase login/session or general database access.

The script uses the same metadata extractor as website imports through the Chrome extension: title, authors and profile links, summary with paragraph/line breaks, fandoms, relationships, characters, additional tags, archive warnings, categories, rating, word count, chapter counts/completion, publication/update dates, and series names, links and positions. It also reads verified chapter-navigation identifiers. It does not read/upload chapter prose, AO3 passwords, login forms or cookies. Visiting an unsaved work queries its library state but does not save it automatically. Adding a work captures a snapshot in the tracker's existing private automatic metadata layer, so old chapter counts do not become permanent manual overrides as a work grows. Existing metadata overrides, favorites and unrelated fields are preserved. When saving from a later chapter without a work summary, the script retrieves the work’s first page and imports its summary and formatting while keeping the selected chapter progress. Empty summary blocks do not erase that summary; chapter summaries are excluded. If retrieval fails, the draft stays open for retry. For saved works, open **Edit → Collect Metadata** to capture the open AO3 page again. Reload AO3 first to include its latest changes. Recollection preserves reading progress, personal fields, manual corrections and your unsaved editor draft. Failed recollections can be retried. The new metadata refresh migration must be applied before using this option.

Website and Safari saves compare each edited field with the version originally loaded. Changes to different fields merge automatically. If both devices changed the same field differently, saving pauses to show your draft and the currently saved value. Choose either version, or edit/combine notes, then save resolved changes; the server checks again before writing. Reading status and chapter count are reviewed together. **Reload Saved Entry** updates untouched fields and preserves local edits, with the same conflict review. Restored Safari drafts retain their original baseline; older drafts without a baseline receive conservative conflict checks. Apply `20261019000201_safe_library_edits.sql` before deploying the updated app/userscript. Older installed scripts keep their original version guard until replaced.

While a panel is open, the footer displays the installed version and links to Settings with update instructions. Bump `package.json`'s version before distributing changes, rebuild, and replace the same `.user.js` file in the selected Userscripts directory. Open the Safari popup and reload AO3; verify the footer version. Storage is retained when updating the same script; changing its name or reinstalling may require pairing again. The generated `.meta.js` is available for distribution, but no automatic update URLs are configured. Userscripts documents limitations in its update process, so manual replacement is the supported update path. See [Userscripts metadata and installation documentation](https://github.com/quoid/userscripts#metadata).

Automated tests cover defaults, credential boundaries, ownership, revocation/expiry, atomic saves, stale-write rejection and failure recovery. Actual iOS Safari and the App Store Userscripts runtime still require a device check after deployment.

- Series pages show the same connected library toolbar. Add the series alone or select installments and set individual progress, notes, ratings, tags, and collections. Already saved works retain their details. For paginated series, save each listing page; saved series installments are combined across pages.
