The ordered SQL migrations, generated types, and source files are authoritative for exact database signatures and validation.

## Purpose and Current Scope

Beyond the Archives is a private AO3 library and reading tracker. It separates a work’s factual AO3 information from each reader’s progress, corrections, notes, ratings, and organization. Organizer browsing keeps search and filter edits pending until Apply is clicked. Applied-filter chips describe the active results; Clear All Filters resets immediately. The filter footer places save-default buttons before Clear All Filters and Hide, with the latter pair below on mobile. The expanded Hide action matches the toolbar toggle, and mobile places Work Status beside One-Shot. Sorting and grouping remain immediate, save browser preferences before navigation, and preserve pending edits. Each new history entry refreshes saved filter defaults and ordering, including when rapid navigation retains the dashboard instance; explicit URL values still override defaults. Transient tooltips allow pointer input to pass through; pinned help remains selectable and closes on an outside press, a second trigger click, or Escape. Automatic-collection rules continue to save through their enclosing collection form. Readers can save a work even when AO3 metadata is inaccessible, then correct or recover information without losing reading history.

The application has three cooperating parts: a responsive website, Supabase authentication/database/functions, and optional browser companions. Direct metadata retrieval uses a separately running trusted worker. A development-only sample library substitutes browser storage for account-backed persistence.

Implemented capabilities include manual and link entry, bulk imports, CSV review, browser-list scanning, series previews and saved series details, author pages, advanced filtering, automatic collections, chapter history, exports, full backup restore, and DNF archiving. `/stats` provides calendar-filtered reading statistics. Automatic email notifications, automatic future-installment import, and scheduled backup creation are not delivered features. The Features page is an anchored guide to implemented workflows, including standard-tag verification, with navigation on desktop and mobile. Early phase reports may describe plans beyond the current implementation.

## BookFusion Linking

The work metadata editor stores a private BookFusion Link and explicit book/bookmark kind. Work info displays Wayback, Unfolded (▤), and, for a valid saved link, Bookfusion (overlapping-books symbol) in that order. Unfolded uses “Open in archives unfolded EPUB reader” hover/focus text and the existing work-specific reader destination, only when the connected reader has a matching downloaded or cloud-saved EPUB. Bookfusion uses “Open in Bookfusion”. The separate BookFusion Link information section and display-customization field are removed. Book links omit queries/fragments to avoid a fixed location; bookmarks retain their exact URL. Only HTTPS destinations on `bookfusion.com` or `www.bookfusion.com` without credentials or custom ports are clickable. The shared work-card/details bookspine footer places Open in BookFusion after the caught-up action. BookFusion controls reading position independently of organizer chapter history.

The implemented Calibre report workflow exports AO3 URLs, upload identifiers, titles and authors with a read-only Python helper, then previews exact AO3 work-ID matches for selected-link saves. Missing links and identities, duplicate matches, and concurrent changes require review. Upload identifiers alone do not generate URLs. No live companion integration or BookFusion progress synchronization is implemented. See [BookFusion](BOOKFUSION.md) for the report contract, limits, and complete procedure.

## Main Workflows

1. An operator configures Supabase, enables the private-beta hook, and approves signup email addresses. Approved readers use Create Account, confirm their email, and sign in. Operator invitations also support password setup. Recovery links return through `/auth/callback`.
2. The reader adds a work manually, submits a link, recovers metadata from an EPUB, reviews CSV data, or explicitly starts a browser scan. Personal library identity can persist before metadata retrieval succeeds.
3. Library and Currently Reading show server-paged results. The reader filters, groups, sorts, opens details, edits personal information, or follows an AO3 reading link.
4. Website reading controls change saved progress/status. Footer chapter edits save both atomically: zero → To Read, intermediate chapters → Reading, and all published chapters → Finished for complete, abandoned, or deleted works or Waiting for Updates for ongoing works. Unknown publication status remains Reading for positive progress; a complete work with only a known total finishes at that total. Mark as Caught Up applies the published count and offers Undo for both fields. The AO3 companion also supports in-page reading actions and chapter records from the loaded chapter.
5. New metadata observations refresh factual information. Private manual corrections retain precedence; proposed historical reading changes require review.
6. Settings provides display preferences, retrieval choices, exports, backups, restoration, and optional DNF cleanup. Full backups provide recovery of details that a compact DNF archive intentionally omits.

## Work Identity and Metadata Contract

Export Work Metadata is available in work-tile action menus and beside work-page metadata refresh controls. One shared confirmation/format chooser offers JSON (default) and CSV. Downloads contain one saved work’s effective metadata and private entry fields; CSV reuses the library export’s field mapping, Unicode handling, and spreadsheet formula escaping. JSON uses the versioned `beyond-the-archives-work` envelope and omits the transient `detailsLoaded` flag. Exporting does not refresh metadata or change saved data.

| Data | Specification |
| --- | --- |
| AO3 identity | Normally a unique numeric AO3 work ID; one private library entry per account/work. Deleted bookmark-only entries can have no AO3 work ID. |
| Submitted link | Preserve the original work/chapter URL separately from a verified canonical work URL. Editing or EPUB recovery cannot replace an existing work’s identity. |
| Canonical URL | Normalizing a candidate URL alone does not verify it. Verification requires matching AO3 evidence. |
| Factual metadata | Title, authors and optional author links, fandoms, plain/formatted summary, categorized tags, rating, language, words, published/planned chapters, dates, statistics, series membership and available identifiers. |
| Effective metadata | Shared factual information and account-private browser observations are combined with private manual overrides. Manual corrections take precedence. |
| Unknown values | Nullable chapter/word counts and completion remain unknown; zero is not a substitute for missing information. Missing later observations preserve saved fields. |
| Publication status | `unknown`, `in_progress`, `complete`, `abandoned`, or `deleted`, independent of reading status. | One-shot | Complete single-chapter works or exact case-insensitive “One-shot”, “One shot”, or “Oneshot” AO3/personal tags; a private manual override can correct detection. |

Legacy unclassified tags are available to broad search but excluded from category-specific filters until classified. ## Reading and Personal Data Contract

The seven reading statuses are `to_read` (To Read), `reading` (Reading), `paused_reading` (Paused Reading), `waiting_for_updates` (Waiting for Updates), `re_reading` (Re-Reading), `finished` (Finished), and `did_not_finish` (Did Not Finish). Numeric corrections during Re-Reading preserve that mode, including zero, until completion. Begin Re-Reading resets only current progress and retains history. Active ongoing works with all published chapters read become Waiting for Updates. `hiatus` (On Hiatus) is a private publication override beside Abandoned, with quick actions for both; it remains distinct from the reader's personal status and waits for updates when caught up.

- Progress is the number of fully read chapters. Chapter IDs are identifiers, not positions. Only explicit verified numbered chapter mappings establish positions or trusted next-chapter destinations.
- A verified explicit chapter-link location at position N represents N−1 fully read chapters. Unverified links retain their original destination and do not invent progress. Explicit chapter-link actions and metadata-only refreshes have different intent; refreshes preserve reading location.
- Caught Up finishes a complete, abandoned, or deleted work or puts an ongoing work into Waiting for Updates. Unknown publication status retains the current reading status. Reading all known published chapters of an abandoned work can finish it despite a larger planned total.
- Mark as Finished uses published chapters, falls back to planned chapters when only that is known, and preserves progress when neither is known. Pausing retains progress; resuming restores the applicable active reading state.
- Rereading opens another start/finish range while preserving the earlier range. Imported finishes may have an unknown start. Pause/resume retains the current range. Reading dates represent recorded events, not measured time spent reading.
- Favorites, editable Recs, personal star ratings, notes, tags, and collection membership are private. Source bookmark Rec observations are distinct from the reader’s editable Rec choice. Personal ratings use one through five stars or no rating.
- Concurrent edits use saved baselines/conflict review rather than silently overwriting newer personal changes. Supported reading/deletion actions offer a two-minute Undo snapshot managed above route changes.

For unsaved works, the first-chapter top bar orders Add to Library, To Read, and Reading; Reading saves `reading` with progress 0. Only that chapter’s top bar offers To Read. The first chapter’s bottom bar and both bars on later chapters offer Mark Read; the bottom of a complete final chapter uses Finish Fic (including one-shots). Read actions save the entry, advance through the selected chapter, and reuse chapter-history capture. In Entire Work, each chapter’s trailing bar uses its own ordinal. Unknown/ambiguous chapter positions omit read actions; the latest WIP chapter remains a normal caught-up action. Listing tiles retain their separate To Read shortcut.

Companion Mark Read/Finish actions on a loaded chapter can record chapter number, counted words, server timestamp, and reread evidence. Word counting excludes summary, notes, and controls; only the count is uploaded. Marking through a later chapter also records earlier newly completed chapters, counting their text locally from the loaded page or one full-work fetch. Unavailable text yields an unknown count. Confirmations below both the top and chapter reading bars offer clickable Undo buttons, which restore prior reading state and remove the entire action’s history records using a server snapshot and strict version guard. Undo has an always-underlined label, a bordered target at least 44px tall, theme-aware contrast in day/night modes, and visible keyboard focus. Manual progress changes do not generate historical chapter word counts. Chapter records appear in Story Information and survive backups and DNF reading archives. Details are in [AO3 metadata capture and display](IMPLEMENTATION.md#ao3-metadata-capture-and-display).

## Search, Navigation, and Collections

Library and Currently Reading reuse the same query/filter system, cards, sort/group controls, and suggestions. One-Shot follows Rating in the filter controls, with an independent Crossovers Allowed/Only/Exclude selector. Crossovers means more than one distinct normalized fandom on a work; series match individual installments. Word Count supports descending and ascending order with unknown values last. Applied-filter chips remove one selection or tag term immediately. The toolbar uses Apply Filters, with its extra width taken from Select Fandoms; dropdown counts follow names in parentheses. Expanded actions share the Hide control height, fandom popups are wider within the viewport, and fandom names wrap inline. Reading and removal confirmations show one popup at a time; a new notification replaces the previous one. Library applies filters within the selected shelf/collection. Currently Reading has active/status sections, including To Read, Waiting for Updates, Paused Reading, and Re-Reading. New Chapter requires an existing undismissed notification and verified unread destination; browsing does not itself fetch updates or create notifications.

Information icons share secondary-surface help boxes with maroon borders that expand to fit all text without internal scrollbars. Icons are centered in a contrasting hover/pinned background. Hover or focus reveals help; clicking pins it open and keeps the icon maroon across pointer/focus changes. Clicking again or Escape unpins it. This behavior applies to information help only; other hover text keeps its existing behavior and styling.

The search grammar supports spaces for AND, `||` for OR, quoted phrases, leading `-` for NOT, `*` wildcards, and backslash escaping. AND/NOT bind before OR. Matching ignores case/accents and ordinary terms can match substrings. Invalid syntax shows an error. Search scopes include Any Field, Summary, and Notes. Escape dismisses search suggestions without clearing pending search text or applying filters.

Fandom selections are OR conditions; selected categorized tags must each match. Publication status, AO3 content rating, personal rating, favorites, Recs, notes, one-shot, series membership, and saved metadata dates provide additional predicates. AO3 update-date bounds are inclusive UTC dates. Clear filters retains current sort/group preferences, including when a filter-panel snapshot carries older ordering values. Shelf changes use the latest applied or cleared filters even before the preceding URL transition commits; destination-specific saved defaults still override them. Grouping supports fandom, author, and series; multi-valued works can appear in each relevant group.

Canonical tag evidence augments exact canonical selections with AO3-verified synonyms. It never substitutes related tags, subtags, or a guessed spelling match. Each verified canonical tag appears once under Standard Tags, discoverable by its synonyms; synonyms are omitted as separate suggestions. Other / Unverified Tags follow. Suggestions are deduplicated ignoring case and accents, using the complete paginated account cache even when a tag is outside the eight active lookup candidates; verification failures are reported in the open suggestions. Organizer tiles order relationships, characters, Additional Tags, categories, and archive warnings; reader tiles retain Additional Tags first. Organizer tiles also prioritize verified canonical tags and synonyms within each category, preserving original spelling and relative order within each verification tier. Reader pairing does not supply tag-verification evidence, so reader tags retain source order within categories. Original fic tags remain unchanged. The same matching applies to ordinary results, series, automatic collections, and counts. Resolver details and refresh/retry rules are maintained in [Canonical Tag Suggestions](IMPLEMENTATION.md#canonical-tag-suggestions).

Manual collections store explicit memberships. Automatic collections use the shared filter predicates and derived memberships; conversion to manual snapshots the current matches. Names, summaries, colors, symbols, order, and appearance are editable. Hiding is a browser preference and does not delete content. Deleting a collection preserves its works. Bulk collection selection and movement reuse existing shelf controls. One Shots is an editable/deletable starter automatic collection, not a shelf recreated on every read.

Paged queries filter before pagination and use deterministic sorting with an identity tie-breaker. Random sort retains its seed while paging/reloading. Pages default to 50 items and allow 25/50/100/250. Browsing URLs preserve query state and support return-position restoration. Pending restoration stops on pointer, keyboard, click, wheel, or touch input so it cannot reclaim focus or scrolling from an active interaction. Toolbar page-size overrides reset on reload; Settings owns the persistent default. Library/collection filter defaults are browser-scoped; saving a library-wide default clears collection-specific defaults. Pages above 100 results use variable-height virtualization; browser Find sees mounted cards only. Tiles defer unopened action menus and hidden metadata construction while preserving saved display layouts, menu dialogs, and reading controls. Work and series action menus stay within the viewport above the fixed mobile navigation, opening upward or scrolling internally when space is limited.

Series queries materialize merged work and metadata stages once per series and build normalized text only for an active search scope. Series-only result pools exclude work cards after retaining their context for series aggregation. Saved works are grouped once across series, and the merger receives a stored compact input derived atomically from each effective search document. Series context reads are independent of full work-card documents and omit HTML summaries and per-chapter date maps; full work metadata retains the dates. The client queues series page, suggestion, catalog and navigation-count reads so results load first without concurrent series scans. Browsing carries compact saved-work identities and series organization through the shared merger; facets skip card payloads and materialize only suggestion fields. Full detail callers retain their original payload contract. The existing owner-private revision cache also retains one merged series pool for subsequent collection, sorting and filtering reads; ordinary matching identities and the series pool share the existing 20-entry bound. Client page caching retains 20 pages. Source edits advance the same revision used by the existing caches. Ordinary work reads remain parallel. Series requests select and hydrate the page from the same pool; work-only requests retain the revision-bound identity cache. Compact navigation avoids full preview aggregation. Catalog and navigation work context read a stored compact document instead of full source overlays, history, chapter maps or summary HTML; the same compact membership/identity fields select cold series candidates. Catalog cancellation uses the existing request signal handling.

The current query architecture uses owner-scoped effective search documents, indexed navigation fields, derived automatic memberships, revision-based identity/count caches, and separate facets. The client checks revisions on foreground return and import completion, with a 45-second visible-tab fallback. A new result’s cards/count commit together; retained rows keep their original numbered range during page and page-size changes, with Updating… feedback until replacement results arrive; errors retain known values with retry instead of displaying a false zero. Suggestion and result failures share an alert/retry layout with underlined retry labels on hover or keyboard focus, and consistent cause-specific messages for timeouts, expired sessions, missing migrations and connection failures. Full identities/details load on demand. Exact cache budgets, benchmark conditions, and rollout requirements are maintained in [Performance](PERFORMANCE.md#revision-based-navigation-and-counts).

## Series Contract

The Series collection combines series inferred from canonical AO3 memberships of at least two distinct saved works with explicitly saved full series and series retained by personal organization (notes, favorite/Rec, collections or Finished status). Named series without an AO3 ID remain filterable but cannot create a series card.

A basic inferred series page requires at least two distinct works in the current reader’s library; repeated membership observations count once. Direct visits to an ineligible series show an explanation and an AO3 link instead of organizer controls. Saved series records retain the existing visibility rules independently of this minimum. Removing a work can remove an inferred series from browsing and its direct page. A basic series page derives from saved library works and memberships without fetching AO3. Official total words/completion remain unknown until full details are loaded; basic totals cover saved works only. Series completion is distinct from series reading status and from completion of individual works.

An explicit preview is temporary. **Load** saves a private full metadata snapshot, potentially including unsaved works; it does not import those works. **Refresh** updates that snapshot. **Refresh Works** uses the existing page metadata batch/polling flow with all saved installments, independent of the unsaved-work visibility toggle. It waits for the complete library catalog, deduplicates AO3 work IDs, excludes unsaved preview works and unrelated library works, preserves reading locations and private corrections, disables repeat submission while active, and reports queued, completed, partial and failure status. Empty series and sample previews cannot submit refreshes. **Remove** discards downloaded details while preserving saved works and private series organization. Notes, favorites, collections, and finish actions can operate with a minimal series identity.

Reading status is derived from saved installments: active reading or a Finished/To Read mixture is Currently Reading, all To Read is To Read, and all Finished is Finished. Unsaved preview works do not participate. An explicit Finished state can remain when no works are saved; adding a work recalculates it. Marking a series Finished changes only saved works and preserves their other personal fields.

Series link imports, scanned series, and Related Series review reuse the shared work picker. Each list, CSV, pasted-link or Add Story link import has an unchecked **Check Series Containing Imported Works** option. Off limits discovery/review to directly bookmarked series and supplied series links or series lists; on also checks memberships of imported works. The existing Choose/All behavior applies independently. Scans persist this choice across pause/resume and batches; older saved scans retain their original all-series behavior. Completion review excludes already reviewed series and includes opted-in CSV works already kept in the library. Save appears only for series absent from saved series records and verified memberships of saved works. Save controls use compact vertical padding to preserve review spacing; their help remains visible outside scrolling header/footer controls. Loading previews can be cancelled with Cancel, close, or Escape; cancelled reviews ignore late responses and cannot automatically import works. Saving details and submitting imports still block dismissal. Completed writes release the picker before background library refresh finishes. A targeted series refresh keeps the loaded catalog available for subsequent saves; additional unknown revisions still trigger catalog reconciliation. Failed writes retain downloaded previews for retry. Selection IDs, expanded series, reading status and review page persist in this browser for the ten most recent reviews per account. Scan drafts are scoped to scan and batch and reopen automatically after reload using saved companion checkpoints; other reviews restore choices when the same links are reopened. Storage failure shows a warning without blocking current selections. A sticky footer shows the selected-work count. In scan reviews, **Import Selected Works** imports checked installments without closing the picker, deleting checkpoints or advancing the scan; saved installments become Already Saved and remaining choices stay available. Its sticky footer shows the current saved-page operation and completion summary; library/history refreshes continue after the import completes, and refresh failures do not mark saved works as failed. Directly scanned works wait for batch finalization. The incremental Import Selected Works and Import Batch and Continue buttons have hover descriptions distinguishing staying in Work Selection from closing it and resuming scanning. **Import Batch and Continue** finalizes the current review and resumes scanning; **Finish Import** completes the final batch. Successful finalization or scan discard/replacement clears that draft. Header/footer controls hide it immediately after saving; Save All Series skips existing series and disappears when none remain to save. Overlaps deduplicate; no unselected work is imported. Saving full series details is independent from importing installments. Named manual series without AO3 IDs remain filterable but have no AO3 series page. See [Series Import Previews](IMPLEMENTATION.md#series-import-previews) and the [companion guide](../companions/chrome/README.md) for listing and selection limitations.

## Import and Recovery Contracts

Mass Import from AO3 uses four tabs: Work or Series Links (default), AO3 Library Sync, CSV (Bookmarks or Marked for Later), and Calibre (Bookfusion). One shared Previous Batches implementation appears at the bottom of the active panel. Forms remain mounted so switching tabs preserves drafts and active scans; the `tab` URL parameter retains the chosen section across reloads. Tabs share the statistics page’s keyboard navigation and styling. The mapping form is titled Link Books from Calibre (Bookfusion).

Reading corrections are scoped to the current sync’s recorded reading-repair entry IDs or the latest CSV import’s returned correction IDs. CSV scope IDs are retained under the provider account’s browser-storage key. Listing, totals, paging, acceptance, and keeping history use the same server-side scope; a section with no known scope IDs shows no unrelated corrections. Owner checks and saved-reading snapshot guards remain enforced. See [Repeat Import Repairs](IMPLEMENTATION.md#repeat-import-repairs) for the migration dependency.

| Method | Behavior and Limits |
| --- | --- |
| Manual entry | Work URL and title required; optional personal/factual fields; no AO3 request needed to save. |
| Wayback snapshots | Fixed 14-digit HTTPS Wayback captures wrapping supported AO3 work/chapter links; optional `id_`/`if_` modifiers. Retains snapshot URL, deduplicates by AO3 ID, retrieves archived metadata privately via the existing worker or Chrome capture. Imports do not accept archived series/list scans or wildcard history URLs; the separate Open in Wayback Machine action can discover recent fixed work captures. | Archived imports are automatically marked Deleted through the existing private availability/publication projection, including after metadata retrieval; personal reading state is preserved.
| Work/chapter links | Up to 2,000 URL tokens per submission; database validates identity independently; saved entries and persistent metadata jobs are separate. |
| Series links | Preview and select installments before importing; saving details does not automatically import missing works. |
| CSV | Up to 2,000 unique works and 20 MB per review; supports scraper exports and source-list distinctions; personal-data conflict review supports Keep/Overwrite. |
| EPUB | Up to 50 MB; metadata-only local recovery with bounded decompression and corruption checks; encrypted metadata unsupported. Missing fields preserve editor values, and existing identity cannot change. |
| Library Sync | Explicit browser scan with durable account-scoped checkpoints; page-sized import transactions; 500 pages per batch across listings/series. CSV and scan imports batch effective-document refreshes until all source updates finish, projecting each affected work once per transaction. Failures retain checkpoints/selections and expose server code/message plus saved page/series context when available. |

Add Story offers **Import Source → Import from Wayback Machine** with a dedicated snapshot URL field; pasting a supported snapshot in the normal link field selects this source automatically. The work details page observes the originating import batch so metadata and failures remain visible when retrieval finishes during navigation. Wayback imports preserve the historical source in submission history and new entries. Replay-rewritten links are normalized for metadata/identity parsing. Historical observations remain private, do not verify a live canonical URL or current availability, and preserve manual corrections. Archive requests cannot redirect to live AO3 or another work; no current chapter-index request is added. Saved reading destinations retain the capture instead of assuming another archived chapter exists. Missing archive metadata leaves the saved identity editable. Chrome/Edge v0.7.6 requires archive host permission; Safari is not used for import retrieval.

Saved AO3 works offer Open in Wayback Machine in their action menu and beside Date Updated on their details page. On mobile, Date Updated keeps its normal statistics column and the archive action stacks below the date. The authenticated `/wayback` route opens in a separate tab, invokes the read-only `wayback-lookup` Edge Function, and automatically navigates to the newest verified capture among its bounded recent candidates. Adult-warning pages with a matching confirmation link are accepted; login-only pages, mismatched work identities, and replay redirects to live AO3 are rejected. The function checks base, adult-confirmed, entire-work, and saved chapter/collection URL variants, reads up to five recent successful HTML captures per variant, and verifies at most eight distinct captures within 25 seconds. This is a best-effort recent search, not an exhaustive proof of the newest readable snapshot or of complete chapter coverage. Missing captures, verification failures, or archive outages offer the canonical work’s calendar and retry without changing library data. The function requires deployment; an unavailable function leaves the calendar fallback usable.

Link submissions can save bare work identities while retrieval is pending, restricted, or unavailable. Import history preserves inputs/results and exposes retry/cancellation where allowed. An explicit existing-work chapter import may change reading location; bulk repeat-import observations preserve personal history unless the reader approves corrections. Later personal edits invalidate conflicting proposals or queued inference.

New bookmark entries can infer Finished when their bookmark date is later than work update date; earlier/same-day bookmarks remain Reading. Optional chapter-date verification estimates only a consecutive prefix strictly before the bookmark day. Missing or ambiguous evidence remains unconfirmed. Marked for Later adds new works as To Read and keeps existing entries. These are import inferences, not proof that AO3 tracked reading. CSV personal overwrite remains an intentional replacement path separate from factual metadata refresh.

Full scans support user/pseud Works, Bookmarks, Series, Marked for Later, filtered listings, tag/search pages, and AO3 collections. Combined collection scans visit Works and Bookmarks; Import to New Collection can create a manual collection. Series encountered are expanded once, without recursive discovery of every other series. External bookmarks are skipped. Deleted bookmarks retain available bookmark identity and information; absence from a list never proves deletion.

Quick Sync is limited to complete unfiltered user Bookmarks/Marked for Later lists. It stops after the first overlapping page, retaining all observations on that page. A baseline advances only after the complete scan’s imports are acknowledged. Ranges, early-ended scans, and intermediate batches do not advance it. End Scan stops new primary-list discovery but finishes discovered series and enabled chapter-date checks before review. Continue From Previous Scan resumes at the next uncaptured page, before or after importing results; unimported checkpoints are preserved.

Scans use one owned AO3 tab, durable page checkpoints, and 15-second default spacing configurable from 5–3,600 seconds. Restrictions, login requirements, unexpected pages, missing tabs, and timeouts pause for manual resolution. DOM capture cannot read HTTP Retry-After headers. Reconnect the same account after restart to resume; private checkpoint data stays on that device until imported/discarded. Saved reports persist separately and expose skipped-entry/chapter-date evidence, factual repairs, series repairs, and proposed reading corrections. The report selector pages ten reports at a time.

The bookmark-conflict results panel compares saved and incoming personal data in a two-column grid (one column on small screens), with maroon hover-underlined work links. Each work has explicit Keep Saved Data and Use Incoming Bookmark actions. Applying incoming data replaces notes, tags, and reading state through the existing listing import with the post-import expected version; stale reviews are rejected. Deleted-bookmark choices replace notes/tags only. Unrelated ratings, favorites, collections, and manual metadata corrections remain protected.

Repeat observations update nonempty factual fields while preserving manual corrections; zero statistics and false completion flags are meaningful values. Source bookmark observations and reading provenance remain distinct from personal data. Review Reading Corrections can accept individual/multiple proposals or keep history; reading-only approval never replaces notes, tags, ratings, favorites, or collections. See [Repeat Import Repairs](IMPLEMENTATION.md#repeat-import-repairs) for provenance and deployment dependencies.

### Future Implementation: Vector Search
