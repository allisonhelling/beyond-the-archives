# Source Assumptions And Phase A Audit

Audit date: 9 November 2026. Scope: A1–A7 of `to_implement/3. PHASE_A_IMPLEMENTATION.md` in the parent workspace. Read alongside the multi-platform recommendations, tag-filter matching proposal, crossover proposal, and [implementation guide](../IMPLEMENTATION.md). These proposals are requirements/design inputs, not evidence of deployed behavior. No provider integration, migration, protocol change, generated type edit, or production deployment is included in Phase A.

## Baseline And Confidence

Audited `main`, base commit `f60b989` (4 November 2026), plus the existing dirty working tree. Existing changes span organizer, reader, tests and documentation; the pre-existing untracked `20261109000100_work_id_search.sql` is included in the audit and embedded migration replay. It was not authored by this phase. Hosted migration/deployment state was not inspected. The complete ordered local chain, not the outdated upgrade summary at the top of IMPLEMENTATION.md, defines the audited database. See [migration ledger and active dependencies](source-data-flow.md).

React/TypeScript/Vite organizer and independent reader coexist with Node and Deno entrypoints, browser companions and sample/offline repositories. `src/types/database.ts` is generated by `scripts/generate-test-types.mjs` or Supabase CLI; it is not a design surface. `scripts/test-database.mjs` applies every ordered SQL migration to disposable PGlite with minimal Auth/Storage schemas. During this audit the chain was replayed and resolved definitions read through `pg_get_functiondef`, including dynamically patched functions. This verifies local SQL composition, not PostgREST, GoTrue, Storage HTTP, hosted RLS configuration or deployment.

Implemented: AO3/Wayback URL imports, manual and EPUB recovery, private observations/overrides, AO3 canonical/synonym matching for relationship/character/freeform, indexed owner-private search and legacy name-count crossover filtering. Proposed: Any/All/Custom tag expressions, source-qualified fandom mappings/hierarchy evidence, `ao3_hierarchy_v1` and its three-state classifier. No fandom resolver/hierarchy schema or classifier version exists in the audited chain. “Platforms” in reader-availability filters means Unfolded/BookFusion destinations, not fiction-source ingestion support.
