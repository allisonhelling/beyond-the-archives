Each import is fully parsed, checked, sanitized, and hashed before an IndexedDB write. Failed validation or storage leaves the previous version intact. Replacement and active-version updates share a single transaction.

Imported prose uses an allowlist. Scripts, forms, event handlers, styles, frames, SVG, and executable URLs cannot reach the renderer. Raster resources use local Blob URLs, which are revoked on view teardown. External images are rejected. HTTP(S) references open in a separate tab with `noopener noreferrer`. Internal links resolve locally. Embedded font obfuscation is allowed because fonts are discarded, while unsupported content encryption is rejected.

## Identity And Versions

An AO3 identity must come from recognizable metadata URLs or front matter. Arbitrary prose references, titles, filenames, and non-URL identifiers do not establish identity. Multiple identities stay standalone. SHA-256 of original bytes identifies exact files. SHA-256 of normalized prose or a stable AO3 chapter ID identifies sections across versions. Duplicate/ambiguous section matches cannot preserve positions. Same ordinal alone is insufficient. Active versions handle `/?work=123`; positive integer `chapter` selects a uniquely numbered local section and resets its opening offset, while absent/ambiguous sections retain the saved position. The same handoff supports `?book=<hash>&chapter=N` after downloading a cloud-only file; `/?work=123&manage=1` opens management. Missing files show an import invitation with no account or server lookup.

Removed versions retain section identity, metadata, position, and local events; EPUB bytes, raster resources, and section HTML are cleared. Previous history remains associated with its original version. A replacement carries the organizer association and matching completions forward; unmatched sections remain unread and require a resume choice. Replacement generates no reading events.

The shared Local Preview frame caps its height at the stage height; embedded `ViewportFrame` previews scale to the available width and viewport height.

## Reader Resume And Library Controls

An account-scoped `reader-open-book:<owner>` localStorage key records the selected EPUB synchronously and clears on an explicit Bookshelf return. Synchronous persistence prevents immediate reload/navigation from restoring an EPUB the user just closed. Startup restores only an existing downloaded, non-deleting book, after explicit work-link and authentication/settings destinations take precedence. Each book has an optional device-local `lastOpenedAt`; catalog projections retain it without adding it to cloud field synchronization. Last Opened is the default sort, and reselecting a sort reverses its direction.

Manage Local Storage defaults to Title ascending. A fixed table layout and column definitions keep widths unchanged across sorts and saved column reorderings. The desktop dialog leaves viewport space around its edges; the shared Dialog handles background scroll locks. Removal feedback renders within that dialog’s native modal layer. Calibre uses the same lock and offers Retry All Failed for failed transfers whose source files remain staged. Long failure text wraps inside transfer tiles.

Reader Account owns compact username, email, and password edits; Cloud Library contains sync, imports, preserved versions, and conflicts. Both username and email edits verify the current password. Successfully resolved conflicts are removed before attempting another sync. Multipart EPUB uploads rejected with the exact No content provided response retry once using the same file bytes and immutable key as a raw upload. Repeated identical sync messages are deduplicated; a failed first cloud pass does not immediately run a second pass. This fallback is verified with a stubbed backend response, not a real iOS storage service.
