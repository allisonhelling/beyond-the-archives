# Reader Implementation Contract

## Architecture And Reuse

`reader` is a separate Vite/React/TypeScript application and release. Its visible brand, browser title, and installed PWA name are `archives unfolded`, preserving the lowercase branding. The npm package is `archives-unfolded`; its origin, IndexedDB name, and existing persistence keys remain stable across the rename. Its application shell, IndexedDB, optional companion credentials, and service worker belong to the reader origin. It imports the organizer's metadata model, status labels/completion helper, AO3 metadata importer, URL normalization, native dialog, ZIP reader, and chapter word-count helper directly from the parent repository source. Those imports do not mount organizer authentication, routing, or network providers. Run builds from the full repository checkout.

Organizer tiles require organizer-specific state and controls. Reader tiles use the same paper/burgundy design, borders, typography, and tile anatomy with reader-owned actions. Both apps import the shared palette, serif font face, and corner tokens from `src/theme-tokens.css`. Reader styling follows organizer `main` commit `0346ab3`: square surfaces and work tiles, compact 36px filters with 4px control corners, inline uppercase filter labels, serif titles, cream page background (`#F7F0E3`), surface (`#fcf7ec`), and secondary surface (`#f1e1d1`). Standard buttons retain 6px corners. The theme toggle stays 40 × 44px in both modes and uses 20px Sun/Moon SVGs with a 2.75px stroke. Reader styling has one token set, one tile class, and responsive variants. No organizer navigation or offline UI has been added.

`src/filters.ts` defines facets, numeric/date fields, option counts, case/accent normalization, exclusion rules, range validation, and the local match predicate. `BookshelfFilters` renders controls from those definitions with native selects and the shared `Dropdown` component. The organizer and reader share `ActiveFilters`, `MetadataTags`, and their CSS. Reader `appliedFilterTags` derives removable labels from the same facet/range definitions as matching, including query, exclusions, All/Any modes, unknowns, and both range bounds. Each removal clears only that value; Clear All resets filters/query without changing sort. The applied row stays below the filter panel or collapsed toolbar, replacing redundant per-dropdown selected chips. A separate toolbar labels metadata search Search and its submit action Apply; it keeps the Fandoms multi-select visible and toggles the full box with Filters/Hide; hiding preserves parent-owned selections. Metadata, numeric, and date groups expand independently inside the box. Publisher is the first advanced facet. Length & Popularity uses six compact boxes in one horizontal row; Publication & File Dates uses four compact boxes in one horizontal row. Both contain horizontal scrolling on narrow screens. Facets use the whole local catalog rather than disappearing as filters narrow results. Selections are arrays; fields, search, ranges, and exclusions combine with AND. Fandoms and languages default to OR within their own selections; characters, relationships, and freeform tags default to AND. Searchable fields expose an All/Any override for multiple selections. Match uses the same label size as other facets and its selector fits the longest option. On the desktop toolbar it sits beside Fandoms, with Search shrinking to make room; narrow screens retain wrapping. Exclusions reject any selected excluded value. Remaining native selects hold a one-element array. Work Link and generic Tag facets are removed; untyped subject tags remain in metadata search. Missing numeric/date fields fail bounded ranges. Numeric zero remains a known value. Dates compare validated `YYYY-MM-DD` snapshots inclusively. Category data is not inferred from arbitrary untyped subject tags.

`WorkMenu` reuses the organizer’s native details/summary action-menu pattern, shared `useDismissible` hook, and dropdown panel styling on shelf cards. Inside a work, the header title opens the same details dialog directly and a dedicated Hide/Show Chapter Bar button controls visibility; no reading-header work menu is rendered. Escape/outside click/focus dismiss it, and the summary retains focus when opening/closing the shared `Dialog` details view. `WorkDetails` loads only the selected `BookDetails` through the existing App management-state loader, derives categorical/numeric/date fields from the shared reader filter definitions, and adds saved summary, all tags, source/series links as text, and local reading information. Only the canonical, validated numeric AO3 work ID becomes an external link. Summaries reuse the organizer’s sanitized `WorkSummary` renderer and shared stylesheet, preserving paragraphs, line breaks, and safe emphasis in shelf previews and details. Package descriptions support escaped HTML, nested markup, and plain-text newlines; FanFicFare summaries retain markup instead of using textContent. Metadata version 2 re-indexes saved EPUBs while preserving reading state. Imported active content and styling are stripped before rendering React elements. Missing fields are shown explicitly, and the view labels publication information as a saved snapshot. `WorkTags` delegates chip markup, separators, shapes, colors, and optional search actions to the shared `MetadataTags` component, with a trailing expansion button. Shared `tagShapes` includes Filled Chips for both apps; the organizer default remains bullets and the reader default is filled. Supplied reader appearance overrides the organizer hook without mounting organizer providers. Category styles are defined once in `metadata-tags.css`. `WorkTags` shares chip markup between shelf and details: shelf chips retain metadata-search actions, the centered +# more button expands/collapses the complete deduplicated list with `aria-expanded`/`aria-controls`, and details show all chips. No content-store or network reads are required to open details. `publicationStatusFromText` is shared by metadata status parsing and `workTags`, omitting exact publication labels/prefixed status fields from chip display without modifying stored metadata, filter values, or similarly named freeform tags. Shelf, reader header, and details reuse the organizer’s `PublicationStatusIndicator`, status map, icon sizing, and Tooltip. Tooltip and indicator CSS each have one shared stylesheet; reader tooltips use portals to escape title clipping, and the reading-header indicator requests bottom placement while other consumers retain their defaults. Work-fact spans have shared bullet separators.

The existing shared `Dropdown` now optionally supports an internal search box and removable selections. Defaults remain unchanged for organizer consumers. Its base CSS is extracted into `src/components/dropdown.css`, imported by both apps; reader-specific corner/checkbox rules remain scoped. Case/accent folding is reused from `src/lib/search-text.ts` by dropdown search, local filter matching, and the existing tag-resolution export. No organizer authentication or tag-verification provider is required by reader controls. Language explicitly disables search. Arrays preserve labels containing commas.

`src/metadata.ts` enriches the shared organizer metadata model with reader-local publisher, language code, publication/update/package dates, and AO3 collection names. AO3 collections are searchable but deliberately have no dedicated filter; organizer collection labels remain independent. FanFicFare parsing reads recognized title-page labels, linked/list values, and two-cell table rows, while ordinary EPUBs use package metadata and known Calibre custom fields. A `dcterms:modified` packaging timestamp is not treated as an AO3 story update. Numeric Story IDs alone cannot establish AO3 identity. Parser references are the [FanFicFare EPUB writer](https://github.com/JimmXinu/FanFicFare/blob/main/fanficfare/writers/writer_epub.py) and its [metadata label defaults](https://github.com/JimmXinu/FanFicFare/blob/main/fanficfare/defaults.ini).

Each book records a metadata parser version. On upgrade, retained EPUBs with an older or missing version are parsed locally once; successful changes atomically update only metadata and its parser version, preserving the original import/snapshot dates, file identity, position, completed chapters, personal notes, organizer association, and pending/history records. Users can repeat parsing with Refresh Local Metadata. Failed refreshes retain their previous catalog and can be retried. Exact duplicate imports also refresh metadata before opening the saved copy. New parser fields do not require an IndexedDB schema change.

`src/epub.ts` performs bounded extraction using the existing CRC-checked ZIP implementation, extended with binary reads and optional extraction limits. Metadata callers retain their prior limits. Each import is fully parsed, checked, sanitized, and hashed before an IndexedDB write. The original file, sanitized sections, and raster resources are committed in a separate content record in the same transaction as the reading-state and catalog records. Failed validation or storage leaves the previous version intact. Replacement and active-version updates share a single transaction.

Imported prose uses an allowlist. Scripts, forms, event handlers, styles, frames, SVG, and executable URLs cannot reach the renderer. Raster resources use local Blob URLs, which are revoked on view teardown. External images are rejected. HTTP(S) references open in a separate tab with `noopener noreferrer`. Internal links resolve locally. Embedded font obfuscation is allowed because fonts are discarded, while unsupported content encryption is rejected.

## Optional Tag Settings Link

`20261029000100_shared_tag_appearance.sql` adds nullable `metadata_preferences.tag_appearance` to the existing owner-scoped preferences/backup record. `tag_appearance_settings` reads/updates just shape/colors with an advisory lock, checked JSON baseline, a six-shape allowlist, six known color categories, and hex color validation. Anonymous calls are denied. Paired `tag_get`/`tag_save` dispatch only after the existing credential/expiry checks and delegate under the verified owner; unrelated library/progress operations are unchanged. Generated database types include the new column/RPC.

Organizer `TagAppearanceSync` migrates current browser tag appearance into an unset account record, publishes later saved format changes, and pulls account updates on focus/foreground/reconnection and every 30 seconds. Layout/profile settings remain browser-local. Cached pending edits are owner-keyed; switching owners does not seed the new account with another owner’s appearance. A conflict retains the local draft until Use Organizer Settings or Keep This Device’s Settings resolves it. Display editors adopt incoming appearance only while clean. Sample mode stays local and mounts no account publisher.

Reader **Tag Format** uses existing IndexedDB preferences for its independent appearance and an opt-in `tagSyncAccount` bound to the paired connection identity. `useTagSettings` reads through the existing companion RPC, caches the organizer snapshot with that account, and refreshes only while linked. The link follows organizer shape/colors; reader editing is disabled while linked. Unlinking restores the preserved independent reader choice immediately, including offline. Disconnection/different-account pairing cannot apply another account’s cache. In-flight reads are ignored after unlinking; refresh failures preserve the existing appearance and show an error in Tag Format. A backend lacking the migration reports the unsupported link without affecting local styles. No reading preferences, EPUB bytes, or layouts are synchronized by this setting.

## Identity And Versions

An AO3 identity must come from recognizable metadata URLs or front matter. Arbitrary prose references, titles, filenames, and non-URL identifiers do not establish identity. Multiple identities stay standalone. SHA-256 of original bytes identifies exact files. SHA-256 of normalized prose or a stable AO3 chapter ID identifies sections across versions. Duplicate/ambiguous section matches cannot preserve positions. Same ordinal alone is insufficient. Active versions handle `/?work=123`; `/?work=123&manage=1` opens management. Missing files show an import invitation with no account or server lookup.

Removed versions retain section identity, metadata, position, and local events; EPUB bytes, raster resources, and section HTML are cleared. Previous history remains associated with its original version. A replacement carries the organizer association and matching completions forward; unmatched sections remain unread and require a resume choice. Replacement generates no reading events.

## Reading And Completion

`model.ts` owns reading range limits and new-install defaults: 14–30 px font size in 0.01 px steps (17.28 px default), and 480–1100 px width in 20 px steps (1100 px default). The font default follows AO3's [`#workskin { font-size: 1.08em }`](https://github.com/otwcode/otwarchive/blob/master/public/stylesheets/site/2.0/21-userstuff.css) with a normal 16 px browser base. Existing saved preferences remain authoritative. Shared slider markup includes live numeric output and accessible value text; range inputs reset inherited text-field padding and borders so native tracks use the full control width.

The renderer relocates the first EPUB heading when its normalized text matches the saved section title: continuous-scroll navigation centers it between equal-width Previous/Next button columns, and paginated reading renders it above the section body. Notes section headings use the same navigation placement, including headings normalized to Author Notes. Chapter Text labels are omitted, and a black divider follows author notes; section accessible names and the chapter selector still expose the section title. `ChapterNavigation` renders identical Previous/Next controls at the top and bottom of each continuous-scroll section in One Chapter and Entire Work modes, disabling endpoints. Only the top navigation has heading semantics; both title positions and paginated headings use `ChapterTitle` with the shared Dropdown, an underlined text trigger, hover/focus color, and a complete chapter list. `textTrigger` and `portal` are opt-in Dropdown capabilities: existing consumers keep their defaults. A portaled panel is bounded to the viewport and positioned above/below its trigger; positioning updates on scroll/resize. `useDismissible` accepts additional element refs so focus/clicks in portaled options are treated as inside the control. Keyboard selection, Escape, and focus return reuse existing Dropdown logic. Closed panels do not construct their option markup. An optional `chapterBar` preference (visible when absent for existing installs) persists Hide/Show Chapter Bar through the existing settings store. Its direct header button hides only the selector/read-controls bar; section navigation remains available, and layout restoration accounts for the height change. The bulk completion button reads Mark Through Ch #, deriving the viewed chapter number from a mapped ordinal, a Chapter # title prefix, or its prose-only ordinal (front matter is excluded). Completion continues to mark the current and all earlier unread prose chapters without duplicating prior events. `Dropdown.renderValue` allows ChapterTitle to leave a numeric prefix undecorated while underlining only the chapter name; options/accessibility retain the full imported label. Paginated navigation uses one document key listener for Left/Right and Page Up/Down, calling the same turn logic as swipes and page-edge taps. It ignores handled/modified/composing key events, open dialogs, and native or ARIA editing/selection controls, and removes the listener when leaving pagination or unmounting.

Positions use file hash and section identity plus an exact viewport snapshot (layout/content mode, font size/width, viewport and content dimensions, scrollTop/scrollLeft), a prose-only character offset and its vertical offset, and the legacy text-fraction fallback. `reading-position.ts` captures/restores these consistently for scroll and pages. Navigation controls are excluded from new text anchors. Matching display/content geometry restores pixels directly; changed geometry follows the text anchor. Legacy fraction-only records remain readable and gain precise fields on the next capture. The lightweight catalog projects only chapter/fraction; detailed anchors remain in book state and require no schema version change.

Restoration-generated scrolls cannot overwrite the saved location; a user scroll away from the restoration target is captured immediately. Layout restoration listens for viewport resizing, fonts, and embedded-image loading, then uses the latest saved anchor. Leaving for the bookshelf flushes position synchronously into the existing serialized write queue before the next book read; pagehide/hidden-tab events also capture it. Metadata/read/status saves preserve the latest position within the same database transaction unless explicitly choosing a new resume chapter. Incoming sync updates preserve local position. Preferences remain independent of file metadata. Scroll and page turns only save position. Explicit reading actions append local event IDs, timestamp, word count, and reread flag. Word counting reuses the companion implementation and excludes summaries/notes when recognizable prose containers are present.

Final status requires every known published AO3 chapter to be both mapped and completed. A short EPUB cannot finish a longer known work. Unknown publication status preserves current status. Metadata timestamps identify the imported snapshot; the current companion API cannot refresh publication metadata. There is no automatic AO3 fetch from the separate reader origin. Users may explicitly choose reading status or import a current version. History survives later metadata changes.

## Storage And Sync Boundaries

`src/lib/reader-connection.ts` in the repository root owns the public hosted backend defaults and shared handoff encoding/validation. The reader defaults to `https://pnrdztfydurupcqwumvr.supabase.co` and its publishable key; these identify the project and do not grant account access. The Connect Organizer form requires only Pairing Code; Device Name is optional (My Reader when blank). The connection label derives from the backend hostname. Self-hosted backend settings arrive through the organizer link and are validated by the existing `readPublicConfig` boundary; privileged keys and non-HTTPS remote backends are rejected.

The organizer’s shared Connect Reader control uses its configured public backend and `manage_userscript_device('create')` to issue a separate reader code. The destination defaults to `https://archivesunfolded.vercel.app/`; organizer `VITE_READER_URL` can override it for self-hosted readers (HTTPS, or loopback HTTP for local development). A new tab is opened during the click with its opener detached; blocked popups fall back to an Open Reader link. The code and public configuration travel in a URL fragment, never a query parameter. The reader removes that fragment from history before mounting, validates it, and automatically claims the one-time code through the existing credential-rotation flow, then saves the reader connection. The form never asks for Backend URL or Public API Key. An existing connection prevents incoming links from replacing its account. Invalid links are discarded, and canceling or completing the form clears its pending handoff values. Device revocation, local files, and account-bound pending updates retain their existing behavior.

IndexedDB schema version 2 uses `catalog` for lightweight shelf/filter records, `books` for reading state, chapter identity summaries, history, personal notes, and remote baselines, and `contents` for original files, sanitized section HTML, and raster resources. `pending` and `settings` retain their existing contracts. The version-1 upgrade walks a cursor one book at a time and splits each original record inside the atomic version-change transaction; failure rolls back the schema and all migrated data. Version-change notifications close the old database connection. Older tabs may need closing before upgrading.

`bookDetails` and `catalogBook` define the shared projections. All book writes update state and catalog together through `putBook`; imports/replacements/removals include the content store atomically. Position, progress, notes, active-version, and sync writes never rewrite content. The shelf reads only the catalog. Opening a book reads its state and content from one readonly snapshot; closing releases the selected book from application state. Manage EPUB reads only that book's state. Metadata refreshes load one book at a time and skip files already at the current parser version unless explicitly forced.

The shelf reuses the organizer's `Pagination` and its shared responsive styles with a fixed 24-item page and the organizer’s inline Page [ ] of # control, including its shared horizontal label styling. Count, pagination, and Sort By share one results-toolbar row on desktop, wrapping at the existing 900 px breakpoint. Filtering/sorting is memoized over the full catalog; search/filter/sort edits reset to page one and shrinking results clamp the page. Catalog metadata and facets remain in memory, so large-library support is not constant-memory or a universal device guarantee.

Storage usage and quota come from `navigator.storage.estimate()` and persistence status from `persisted()`, refreshed on startup, imports, removals, and synchronization. Missing/failing APIs show an unavailable state. Estimates cover all reader-origin storage, including the offline shell, and are not guaranteed free capacity. Original files are never sent to the organizer. Persistent-storage permission is requested after successful imports, but availability is only a statement about a successfully saved reader record. It is not a cross-device claim or a guarantee against browser eviction.

A connection is scoped by a hash of backend origin and paired secret, not by a user-entered label. A new secret creates a separate queue identity. Standalone imports retain their local identity/history when connected. Importing an identifiable AO3 EPUB may match an existing work; manually linking an unlinked book requires confirmation of an AO3 URL. No new organizer records are created.

The adapter calls `userscript_library` through the public REST API, using the paired secret and public API key. Checked saves use the original field baseline. Reading observations use `chapter_read`/`previous_chapters`; server-side atomic progress guards make retries safe after lost responses. Notes use checked `save`, and progress/status use `progress`. Requests are persisted before sending, including a frozen baseline for retries. Pending edits remain ordered and are processed first using individual book-state lookups. Pull refreshes use the existing single-work API with groups of up to four concurrent requests, bounded to 50 linked versions per run. A per-account settings checkpoint records the last completed ID group and timestamp; later runs continue in stable ID order and restart at the beginning after reaching the end. Automatic pulls wait at least 60 seconds between runs; manual Sync Now bypasses this interval. Pending writes bypass the pull interval. Failed groups do not advance the checkpoint; successful writes within a failed group can be safely checked again. A queued edit, changed remote baseline, or changed account/work association detected in the write transaction prevents an in-flight pull from overwriting local changes. No server migration or new batch endpoint is needed. This bounds each run rather than promising immediate whole-library freshness. No maximum-chapter conflict policy is used. Incoming compatible changes merge in the organizer’s existing checked-save function; conflicts retain both values and require review. Use Reader rebases only after explicit confirmation; Use Organizer discards that queued change while preserving local history.

Organizer progress below an already-read chapter cannot manufacture missing events: the server accepts only newly advanced chapter completions. Explicit reread starts queue a new `re_reading` session at zero before its subsequent completion events. Nonconsecutive single-chapter completions keep local history, but the organizer's existing scalar progress model cannot express arbitrary unread gaps. Reader local completed-section records remain authoritative for its completion decision.

Disconnect clears credentials; account-bound events and local content remain. Reconnect/foreground requests arriving during an active sync queue one follow-up run, so an offline startup result cannot swallow a reconnect. No closed-app background sync is promised. The service worker caches only same-origin build resources and does not cache account API responses. Application updates install a complete version before activation; existing open clients retain their prior worker until closed. Deploy releases atomically to avoid deleting resources needed by older tabs.

## Vercel Deployment

Use a separate Vercel project for the reader, connected to the same repository. Set **Root Directory** to `reader`, select **Vite**, and enable **Include source files outside of the Root Directory in the Build Step** under Root Directory settings. Shared components and the root lockfile live outside `reader`; this option is required. See [Vercel’s monorepo guidance](https://vercel.com/docs/monorepos/monorepo-faq).

`reader/vercel.json` supplies the install command `npm ci --include=dev --prefix .. && npm ci --include=dev`, build command `npm run build`, output directory `dist`, and SPA fallback while keeping PWA assets outside the fallback. Both installs include build-time dependencies even when the environment omits development packages by default. The root install resolves dependencies imported by shared source files; the reader install supplies its compiler, bundler, and runtime packages. Vite deduplicates React and React DOM so shared and reader components use the same runtime. The shared offline-shell plugin exposes only its Rollup name and bundle-generation hook, keeping its type contract compatible across the two separately installed Vite copies.

The reader lockfile uses registry packages with integrity checks rather than links into another local checkout. A log showing only 13 linked packages installed followed by `tsc: command not found` can indicate an older lockfile containing local dependency links. Deploy the repaired lockfile/configuration and redeploy without the previous build cache. Also check for installation overrides that omit development dependencies. Node engine-range and npm configuration warnings are separate from that missing-compiler failure.

Validate installation from a clean full checkout with the configured install command and build; a build using existing parent `node_modules` does not verify portability. Keep the root organizer Vercel project’s Root Directory and configuration unchanged. No organizer environment variables are required merely to open the reader; hosted public defaults are included, and self-hosted settings arrive through Connect Reader in that organizer.

## Organizer Availability Reports

The paired reader reports active linked work identifiers only after loading their actual local files. Full reports replace previous availability, including after file removal. A persistent local installation UUID, user-supplied installation name, reader URL, and server report time identify the report. Synchronization reports before processing queued reading changes, so reading conflicts do not block availability reporting. The organizer’s [offline contract](../../docs/PROJECT_OVERVIEW.md#offline-hub-and-reader-availability) distinguishes last-reported availability from local verification and defines setup and expired-session behavior.

Linked chapter completion attempts to refresh publication information online, otherwise uses its saved snapshot. The companion response includes effective publication metadata and observation time. Snapshot updates preserve reading history. Duplicate chapter numbers or AO3 IDs are ambiguous and cannot imply final completion; offline completion messages identify the snapshot update time. Unknown publication state opens Manage EPUB for an explicit personal status choice after all EPUB sections are marked complete.


## Chapter Identity and Repair

The importer excludes `.notes`, `#notes`, and `.summary` ancestors when selecting `.userstuff` for chapter identity and word counts. Full sanitized content still includes author notes. Standard title-page/cover resources and standalone Notes sections are front matter. Duplicate prose hashes or source IDs receive resource-path suffixes, with occurrence suffixes if the spine repeats a resource; unchanged unique IDs retain their existing format. AO3 chapter identity/number verification remains independent of these local navigation IDs.

`chapterVersion` versions the content split independently of metadata indexing. When an older download is accessed, `getBook` reparses its retained file locally and commits repaired chapters/resources and reading-state mappings atomically to `books`, `catalog`, and `contents`. The transaction rereads current state and skips files already repaired or removed, preserving edits made during parsing. No IndexedDB schema migration or server lookup is required. Unique old IDs map to new IDs only through the same file’s unique resource path. History events remain recorded; ambiguous references are retained without assigning them to multiple chapters. Ambiguous completed IDs do not mark repaired chapters complete, and ambiguous positions open the existing Choose Where to Resume dialog. Personal status, notes, links, and original EPUB bytes are preserved.

Synthetic repeated-note/prose fixtures cover unique navigation IDs, prose word counts, and safe state mapping. Browser regressions exercise Next/Previous, offline reopen, and repair of an older colliding-ID download. User-supplied EPUBs can be checked locally without copying their content into the repository.
